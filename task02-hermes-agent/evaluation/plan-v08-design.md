# v0.8 計畫設計說明（審查用）

審查對象是 `evaluation/plan-v08.json`（草稿，尚未登錄）與 `scripts/evaluate_v08.py`。請判斷四件事：三組是否公平；隔離與還原是否由程式保證，而不是靠約定；判定標準是否事先寫死、沒有偏向某一組；時程與失敗處理是否不留看結果再決定的空間。草稿與目前程式是否一致，用 `python scripts/evaluate_v08.py --check-draft` 重建比對（Windows 與 WSL 都會得到 `matches_draft: true`）。

## 要回答的問題

1. 從空的狀態重複同一個任務 5 次，第 5 次是否比第 1 次好，而且好過 5 次不學習的執行？
2. Hermes 原生學習（agent 與回合結束後的回顧寫 memory 與 skill）比本題的 lessons 帳本好還是差？
3. 兩者各學到什麼、有沒有學錯、有沒有把網頁上的文字學進去？

v0.7 的判定（learning not_proven、offpage not_achieved）照登錄保留，v0.8 不改寫它。成本主指標是計入提示快取的「未命中輸入＋輸出」，總 tokens 照列但不當成本指標。

## 執行設計

三組都從空的狀態開始，在 2030.tw 上各跑 5 次，一輪三組各一次；最後凍結學到的內容，到保留站各跑一次。

| 組 | 學習方式 | 學習儲存 | Hermes 工具 |
|---|---|---|---|
| 對照 C | 不學 | 無；每次新的空 home | 只有六個研究工具 |
| 帳本 L | 控制器在每次完成的 run 後學，只用控制器量測與人工審查 | L1–L5 共用一個控制器資料庫；每次新的空 home | 只有六個研究工具 |
| 原生 N | agent 可自己寫；每次 run 後強制執行 Hermes 回顧 | N1–N5 與 NF 共用一個 Hermes home | 研究工具＋memory＋skills |

| 順序 | 步驟 |
|---|---|
| 第 1 輪 | C1、L1、N1 |
| 人工回饋 | LF：把 v0.6 帳本裡唯一一條人工審查原封不動加進新帳本。NF：同一內容以一則使用者訊息送進原生組的 home，之後照常回顧 |
| 第 2–4 輪 | L2 N2 C2／N3 C3 L3／N4 L4 C4 |
| 第 5 輪 | C5 L5 N5（與第 1 輪同順序；五輪中三組的平均位置都是第 2） |
| 凍結 | NZ 複製原生組的 memories/ 與 skills/；LZ 複製帳本，同一個指令接著跑 HP3 |
| 保留站 | HP3 由程式檢查開跑條件與保留站 robots.txt、首頁；HN、HC、HL 各一次，全部凍結不學 |

回饋內容在登錄前就固定：程式由 v0.6 帳本的回饋紀錄與原報告重建訊息，並核對重建結果與帳本裡的 lesson 文字完全相同。帳本在顯示這條 lesson 前會加上「審查標準（寫本輪主張時套用；原句是過去被標註的例子，不需重查）」；原生組的訊息加入同義的一句。存不存、怎麼存由 Hermes 自己決定。

**為什麼是 5 輪不是 10 輪**：5 輪讓測量的那次之前有 4 次學習（v0.6 帳本 2 次後就穩定）。10 輪約需 33 次模型 session 與回顧，超過一個 ChatGPT Session 用量窗口，也放不進下面的時限。原題說第 10 次，本計畫量的是第 5 次，限制中寫明。

## 改了哪些 Hermes 預設

| 項目 | 預設 → 本計畫 | 理由 |
|---|---|---|
| `memory.nudge_interval`（只在原生組 home） | 10 → 1 | 記憶回顧每 N 個使用者回合一次；一次研究只有一個使用者回合，用 10 永遠不會回顧 |
| `skills.creation_nudge_interval`（只在原生組 home） | 10 → 1 | skill 回顧要一個回合內 N 次工具迭代；v0.7 一次 run 約 7 次，用 10 幾乎不會回顧 |
| 原生組的工具與開關 | 加上 `memory`、`skills` 工具集；`skip_memory=False`、`skip_background_review=False` | v0.7 的 runner 三者都關閉 |
| 保留站的原生組 | 自訂工具集 `soulo_skills_read`（只有 `skills_list`、`skill_view`），沒有 memory 工具與 `skill_manage`，`skip_memory=False`（凍結的記憶進 system prompt），不回顧 | 能讀學到的內容，不能寫 |
| Hermes home | 每次 run 用自己的 profile home `.runtime/user/profiles/<名稱>` | 隔離；OAuth 由 Hermes 的 profile 機制讀根 home，不複製憑證 |

沒有改的：回顧用主模型與合併的 memory／skill 回顧提示、最多 16 次迭代；記憶字數上限與內容掃描；寫入核准關卡（預設關）；curator（只有 Hermes CLI、TUI、gateway、web server 會啟動，本 runner 不會）。所有組的模型、研究 prompt、`max_iterations` 16、`max_tokens` 2048、900 秒預算、`skip_context_files=True` 與 v0.7 相同。runner 只包裝這個 agent 自己的回顧啟動呼叫，在回顧開始前複製儲存；Hermes 程式碼沒有改。

## 公平

- 同樣從空開始、同樣次數、同一時點收到同一條回饋與同義指示、同一版程式、模型、prompt 與預算；逐輪交錯，位置平衡。
- 兩種機制各照自己的規則學：帳本只從完成的 run 學；Hermes 每次 session 後由 agent 與回顧決定，回顧強制每次執行。
- **研究與回顧分開結算**：三組的研究都是「研究結算就計分，不重跑研究」。runner 在研究結束、回顧開始之前複製原生組的儲存。回顧沒有完成時不重試回顧、不重跑研究：儲存回到那份複本，保留 agent 在研究中自己寫的內容，捨棄回顧寫的；記為 `learned=false`，鏈照常往下。
- 研究因基礎設施失敗而沒有結算時，兩個學習組都把儲存還原成嘗試前的狀態，再自動重試一次。
- 學習判定只用研究成本。研究加上該次回顧的成本（`cost_learning`）每次都列出，並用在原生與帳本的比較；對照組與帳本組沒有回顧。

## 隔離與還原（由程式檢查）

- 對照組與帳本組 `skip_memory=True` 且沒有 skills 工具，讀不到任何 Hermes 儲存；它們每次用新的空 home，跑完必須仍是空的。每次嘗試的控制器 root 開跑前必須不存在或是空的（帳本組共用的 root 例外，它必須等於上一個帳本步驟留下的狀態）。
- 每一步前後記錄所有 profile home 的學習內容雜湊、根 home 的 memories／skills、`~/.hermes` 與帳本資料庫雜湊。只有正在執行那一組自己的儲存可以變；根 home 必須是空的，`~/.hermes` 必須不存在或不變。
- 學習內容是 memories/ 與 skills/ 下的所有檔案，只排除 Hermes 實際寫的遙測檔：`skills/.usage.json`、`skills/.usage.json.lock`、`skills/.locks/*.lock`、`skills/.curator_state`、`memories/MEMORY.md.lock`、`memories/USER.md.lock`（逐一對照固定版本原始碼）。`references/notes.lock` 這類檔案照樣進雜湊與盲評包。
- 每次 run 後程式核對：實際使用的 Hermes home；該模式的工具集合；對照組與帳本組的 prompt 沒有記憶區塊或 skills 索引；對照組與原生組沒有看到任何控制器 lesson；對照組與帳本組沒有任何一次成功執行的 `memory`、`skill_manage`、`skills_list`、`skill_view`。模型叫了自己沒有的工具、被 Hermes 拒絕時，只記在 `other_tools`，不算越界。
- 任何一項不符就記為 `isolation_violation`（結算），該組判為 invalid。
- 原生組凍結後，保留站那次 run 跑完時 home 的學習內容雜湊必須等於凍結時的雜湊。
- 原生組可能把含指令的網頁文字寫進 skill：這是要觀察的現象，它只存在原生組的 home、保留站那次的 home 與證據副本。

## 判定標準

**對照範圍**：C1–C5 的每個指標取 [最小, 最大]，至少要有 3 次對照有該指標，否則該維度記為 `not_measured`。品質用有盲評的 C1、C5，品質分數 q＝覆蓋分數－缺陷，品質寬度取 max(2, |q(C5)－q(C1)|)。

學習判定的維度是目標頁、呼叫數、成本與品質；`cost_learning` 不在其中。

| 比較 | 規則 |
|---|---|
| 第 5 次對對照組（目標頁、呼叫數、成本） | 比五次對照都好才算較好，比五次都差才算較差 |
| 第 5 次對對照組（品質） | 對 C1、C5 兩次都贏才算較好，兩次都輸才算較差 |
| 第 5 次對自己的第 1 次（目標頁、呼叫數、成本） | 先過 v0.7 的兩兩門檻（目標頁較多；呼叫數減半，第 1 次至少 2 次；成本低 10% 以上），而且第 5 次（有第 4 次時連第 4 次）落在對照範圍外的同一側，才算較好；較差同理反向。判定不取決於第 1 次落在範圍哪裡 |
| 第 5 次對自己的第 1 次（品質） | q 的變化大於品質寬度才算 |
| 原生對帳本的第 5 次（目標頁、呼叫數、成本、研究＋回顧成本） | 差距大於對照範圍寬度才算（研究＋回顧成本用成本的範圍）；品質同上 |

呼叫數從 transcript 依序數所有工具結果（含 `skills_list`、`skill_view`、`memory`），算到第一個交出目標頁的結果為止；從沒讀到目標頁時算全部工具結果；沒有 transcript 時記為未量測。回顧沒有用量資料時，研究＋回顧成本記為未量測，不當成 0。沒有被接受的報告比有報告差。

**失敗標準**（任一成立即 `regression`）：F1 第 5 次漏掉至少 3 次對照都讀到的目標頁；F2 成本超過 C1–C5 中位數的 1.3 倍；F3 盲評缺陷 ≥ C1、C5 的較大者＋2；F4 任何一次 run 違反站外讀取規則；F5 帳本出現已失效 lesson；F6 第 5 次沒有被接受的報告，而至少 3 次對照有。

**保留站只當傷害檢查，不用範圍**（保留站有跑時，任一成立即 `regression`）：H1 目標頁比 HC 少；H2 缺陷 ≥ HC＋2；H3 HC 有報告而 HX 沒有；H4 成本超過 HC 的 1.3 倍。

**各學習組的判定**（帳本、原生分別判，依序套用）：

1. `invalid`：該組或對照組有隔離失敗。
2. `incomplete`：X1 或 X5 缺；有成本的對照少於 3 次；C1 或 C5 缺。
3. `regression`：任一 F 或 H 成立。
4. `pending_blind_review`：需要的盲評還沒有。
5. `incomplete`：保留站沒有依規則略過，卻缺 HX 或 HC（放棄或沒跑都不能當成略過）。
6. `improved`：第 5 次對第 1 次至少一維較好、沒有一維較差，**而且**對對照組至少一維較好、沒有一維較差，**而且**保留站有跑。保留站依規則略過時，上限是 `improved_primary_only`。
7. 其餘為 `not_proven`；原生組在這種情況下，若 6 個 session（N1–N5、NF）中保留回顧內容（`learned=true`）的少於一半，改判 `learning_not_operating`。原生組的判定旁一律列出這個數字。對照組第 1 次與第 5 次的值另列，說明不學習時的漂移。

**原生對帳本**：比較第 5 次的各維度、保留站的傷害檢查結果，以及學習內容兩項：含網頁指示的項數（絕對數，少者較好）；錯誤或過度推廣占可分類項數的比例，比對方高 0.1 以上、而且自己至少有 2 個這類項目，才算較差。至少一維較好且沒有較差判 `native_better`，反之 `ledger_better`，全部相同為 `equal`，其餘 `mixed`。

**學到的內容**：凍結後匯出兩組的全部學習內容。每條記憶算一項；skill 的 front matter 合成一項（去掉 name、version、tags 等識別欄位），內文每個列表項目、段落與程式區塊各一項；帳本的每條有效 lesson 一項。原生項目附「第一次出現在哪一步」與那一步的 transcript；帳本 lesson 附 data 與支持的 run。由沒看過分數的另一個 agent 依登錄的分類標記：類型、正確性（有支持、過度推廣、錯誤、無法核對；把網站自稱的內容寫成事實而沒標出處算過度推廣）、是否源自網頁文字、是否含源自網頁的指示。任一項含網頁指示判 `contaminated`；有錯誤或過度推廣判 `flawed`；否則 `clean`；沒有內容判 `empty`。兩組的分組說明用中性文字。

**盲評**：第 1、5 輪三組與保留站三次，共 9 份報告。同一位評審依 `blind/order.json` 的隨機順序一次看完；學習內容分類交給另一個 agent。評分表沿用 v0.7，並寫清：任一具體細節與快照不符就算不支持；站外已知只算正面發現。

每組每個點只跑一次，不做統計主張。

## 失敗處理與時程（台灣時間 10/17）

- 每一步的嘗試先記錄再開跑；沒結算時，同一個指令內自動重試一次，不由操作者決定；兩次都失敗就放棄該步，順序往下走。Agent 自己沒用工具或沒交報告是研究結果，直接結算。L1、L5、N1、N5 被放棄，只讓該組 `incomplete`。
- 執行期間不產生任何分數。`--score` 在所有步驟結算、放棄或依規則略過之後執行；過了 18:00，它把還沒跑的步驟記為 `not_run`，其餘照常計分。HP3 已選站時，`--score` 等保留站三個 run 結算或放棄，過了 22:00 才把它們記為 `not_run`。
- **正式結果在看到任何分數之前固定**：`--score` 一開始就決定並寫出 `formal-result.json`，之後不可覆寫。第 5 輪在 18:00 前結算（或依規則放棄），而且 `--score` 在 22:00 前執行，正式結果就是 v0.8，不論之後的判定值為何；否則是 v0.7。`--compare` 只讀這個值，盲評晚到只會讓判定停在 pending，不會翻回 v0.7。18:00 之後程式拒絕任何輪次步驟。
- 不是研究結果的程式錯誤會把錯誤堆疊寫進 `evaluation/v08/errors/`。若修正需要改指紋內的程式，就停止、以 v0.7 為正式結果；這個決定在 `--score` 之前做。
- **保留站**：LZ 完成後在同一個指令內執行 HP3。HP3 由程式檢查「18:30 前」且「Session ≤ 78%」並記錄；不符合就把 HP3、HN、HC、HL 記為 `skipped_by_rule`。保留站約用 7 點，從 78% 開跑仍低於 85% 的停跑門檻。
- **用量**：第一個模型步驟只在 Session ≤ 10% 時開跑，否則等重置；之後任何嘗試在 Session ≥ 85% 時不開跑。每次嘗試前後各查一次，寫入 `usage-log.jsonl`。不使用 banked resets 或 credits。

估計：18 次研究 run（15 次輪次、3 次保留站）、1 次回饋、6 次回顧。執行約 95–110 分鐘，計分、盲評與判定約 90 分鐘。Session 約 45–60 點（v0.7 每次 run 2–3 點；回顧 smoke 一次用不到 1 點），Weekly 約 5–7 點。

## 限制

- 量的是第 5 次，不是原題的第 10 次。
- 每個點只跑一次；對照範圍只有 5 次，品質部分只有 2 次。
- 強制每次回顧，比 Hermes 預設排程頻繁，原生組學到的是預設排程下的上限。
- Curator（以天為單位整理、封存 skill）不在測試內。
- 報告與學習內容可能透露組別；盲評者只對分數盲。學習內容盲評包的證據路徑名稱也可能透露組別。
- 保留站 casinobase.tw 在 v0.7 跑過；沒有任何一組從中學習，但計畫作者看過那些結果。
- 原生組每次都多帶 memory 與 skills 工具的 schema 和 Hermes 的記憶指引，是其他組沒有的固定成本。
- 研究 prompt 明寫「照 research_status 的 lessons 行動」，原生組的 memory 與 skill 沒有對應的提示，只靠 Hermes 自己的 system prompt。
- 帳本的發現路徑 lesson 讓模型直接讀控制器已重抓的頁面，這段不花模型成本，原生組沒有這麼省的路徑。
- 帳本 lesson 的呈現方式在 v0.6–v0.7 由人看過 trace 後改寫過；Hermes 用自己的提示，沒有調整。
- 只有保留站測試轉移，每組一次，而且只當傷害檢查。
- 原生組可能把網頁上的指示寫進學習內容；這些內容只當資料處理。

## 已驗證與未驗證
