## 盲評

由另一個未看過分數的 Claude agent 擔任，只收到六份隨機代號的盲評包（`blind/`），依計畫的兩個問題逐項核對 73 個主張與 32 個行動，每個主張都打開引用快照。六份都是 unsupported 0、scope_error 0（`blind-review.json`，逐項依據在 `blind-review-items.json`）。

- 盲評在缺陷數上沒有鑑別力：六份都是 0，I5、I6 成立只代表沒有變差，不代表變好。
- 盲評者把 R1 的 claim:8（「作者及更新標示」）判為有依據，因為頁面確實有「2030編輯部」署名。人工回饋把同一項標為證據不支持，理由是團隊署名不是具名作者。兩者的標準不同：人工回饋較嚴，所以 R2、R3 依回饋補上的限定說明不會反映在盲評缺陷數上。
- 盲評者另指出 R1 claim:9 說 post-sitemap2「內容遭截斷」，但快照是完整 XML。工具回傳給模型的文字確實截在 3 萬字，盲評者判為過程說明、不記缺陷。

## 學習機制的實際行為

| lesson | 類型 | 結局 |
|---|---|---|
| `ffec787a4d7d`、`c5209a7fcd25` | 發現路徑（兩個目標頁經 `/wordcup/` 到達） | R1 學到即 active；R2、R3 使用前由控制器重抓確認；R2 再次讀到而延長效期至 2026-10-23；只綁 2030.tw，HM 看不到 |
| `d2e93aa70fca` | 失敗模式：含 `site:` 的搜尋沒有結果 | R1 為 candidate（不提供）；R2 重現後 active；R3 看到後完全不用 `site:`；HM 以「只在 2030.tw 觀察到，請在此驗證」提示呈現，HM 用了 1 次 `site:` 且有結果，但帳本凍結，沒有撤銷 |
| `f9ef5983aef2` | 失敗模式：不含 `site:` 的搜尋沒有結果 | R2 學習時建立，同一 run 有 1 次成功，立即撤銷 |
| `38b7cba20063` | 人工回饋（claim:8 證據不支持，範圍 general） | R2、R3、HM 都看到；沒有到期 |

沒有 lesson 到期或被否決。

模型對 lessons 的使用方式，引自 trace 的 purpose 與推理：

- 發現路徑被當成線索而不是捷徑。R2 的 purpose 寫「重新驗證歷史lesson指出的分類入口」，R3 寫「歷史lesson僅作發現線索」。兩者都先讀首頁與 `/wordcup/` 再讀目標頁，所以首次命中只從 6–7 次降到 3–5 次，沒有降到 1 次。
- 發現路徑裡「讀了 N 份 sitemap，0 份列出此頁」這句引來反覆查證。R2 的 purpose 寫「檢驗wordcup公開導覽是否同時有sitemap發現路徑；不沿用歷史lesson的缺漏結論」。R2、R3 各讀 sitemap 6 次（4 次抓取、2 次讀片段），R1 為 3 次，B1 為 0 次。省下的找頁呼叫因此花在 sitemap 上。R3 與 B1 都是 8 次模型呼叫，tokens 的差距來自每次重送的內容：R3 多了 sitemap 的回傳，`research_status` 也因 lessons 多出約 2,100 字。
- 人工回饋改變了報告內容。R1 寫「作者及更新標示」；R2 改寫成「署名2030編輯部…編輯部署名不是具名作者或專業背書」；R3 寫「團隊署名不是具名專家背書」，第 4 次呼叫的 purpose 也把「署名」列為核對項目。保留站 HM 主動讀作者頁，purpose 是「核對作者頁有無具名署名、可追溯經歷與外部佐證」；HB 沒有做任何署名查核。B1 沒有提到署名，所以無法判斷沒有回饋時是否會重犯。
- `site:` lesson 讓 R3 不再用 `site:`（R1 用 3 次、B1 用 3 次），但改用的精確引號查詢也有 2 次沒有結果。DDGS 對不含 `site:` 的「娛樂城」也回傳 No results（R2），而封存證據中同一查詢曾有結果。可見失敗主要來自搜尋供應商，不完全是 `site:` 造成；lesson 的敘述有寫出「不含 site: 的查詢 3/6 次有結果」。保留站上 `site:` 兩次成功（HB 1 次、HM 1 次），恢復學習時這條 lesson 會被撤銷。

## 限制

- 保留站：預檢時 `casinobase.tw` 連線逾時，依登錄規則改用備援 `icasino.tw`（`holdout-choice.json`）。
- icasino.tw 每頁標題都帶「LINE 娛樂城」，評測方法頁因此被算成「娛樂城」目標頁；該站也沒有 3A 專頁。保留站的目標頁指標偏寬，I6 的目標頁部分證據力弱。
- 保留站 HM 比 HB 少用 29% tokens、6 次工具呼叫與 4 次 HTTP，但這不是登錄的標準，又只有一次，不能當成改善證據。
- 所有 run 的 off-page 都只列為未知，這是已知缺口，不屬本次評估範圍。
- 訂閱用量：R2 前 Session 24%、Weekly 19%；HM 後 Session 39%、Weekly 22%（`evidence/v06-usage/usage-log.jsonl`）。沒有等待重置，沒有使用 banked resets 或 credits。
