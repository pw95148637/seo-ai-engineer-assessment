【盲評｜同一標準比較多篇文章】
你是未參與寫作的資深 SEO 內容編輯與 YMYL 審稿人。以下幾篇文章以代號標示，你不知道它們如何產生。它們回答同一個搜尋意圖。

請以同一標準逐篇評分（1–5 分，附 2–3 句理由與原句引用）：
1. 細節重視：有沒有無法輕易被 AI 偽造的具體細節，且能追到真實經驗或來源。
2. 讀者價值：搜尋這個意圖的人讀完能不能做出更好的決定。
3. 真人感：讀起來像不像台灣資深玩家在論壇分享的獨立心得（而不是小說、散文或查核報告）；AI 腔、套話、虛假誇讚、刻意的文學化感官描寫多寡。判準見 style-guide.md 的「一、共通」與「二、對外文章」。
4. 誠實與可信：文中具體的經歷、數字、時間、對話能否在 inputs/experience.md（作者真實經驗）或 evidence-pack.md／文中引用的來源找到；找不到的具體經歷視為無法驗證，列出例句。權威來源是否真實、引用得當；計算是否正確。
5. YMYL 安全：有無推薦平台、保證獲利或出金、淡化法律與金錢風險、教人規避銀行或法律。

篇幅長短本身不加分，只看內容對讀者的價值。

另外逐篇列出具體缺陷（1–5 分容易到頂，缺陷數比較看得出差異）：事實或計算錯誤、引用與來源不符、說得比來源重、對不到作者經驗的第一人稱、YMYL 風險（導流、淡化風險、漏掉關鍵提醒）。每條附原句與依據，不列文風偏好。

可核對的事實來源：inputs/experience.md（作者本人的真實經驗）、evidence-pack.md。只用來核對細節是否有根據，不代表文章必須使用它們。請抽查各篇至少 5 個來源或數字。

產出：指定的評審檔，第一段是評分表（列＝五個項目加總分，欄＝各篇代號），接著每篇最大優點與最大問題、整體排名與理由、來源抽查結果。檔末附一個 JSON 區塊，鍵名照下例，供程式彙整：

```json
{"X": {"細節重視": 4, "讀者價值": 5, "真人感": 3, "誠實與可信": 5, "YMYL 安全": 5, "缺陷數": 2}, "Y": {"細節重視": 3, "讀者價值": 4, "真人感": 4, "誠實與可信": 4, "YMYL 安全": 5, "缺陷數": 4}}
```

只依文章內容判斷，不猜測產生方式。
