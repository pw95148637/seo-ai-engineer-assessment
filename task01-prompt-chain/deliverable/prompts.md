# 提示詞鏈各步 prompt 全文

以下是 `prompts/` 各檔原文，依鏈的執行順序排列。主控把整份 prompt 交給新的 subagent，再視需要附上執行時的具體約束（例如選定的意圖、作者經驗的使用限制），那些約束記在每次執行的 `run-log.md`。每步的關卡（通過條件）寫在 `.claude/skills/prompt-chain/SKILL.md`。

## 階段 A

### `prompts/A.md`

```text
【A｜微搜尋意圖建模】
目標：針對關鍵字「娛樂城」，找出至少 4 個真實存在、常發生的 Micro Search Intent，作為一篇深度文章的選題依據。

輸入：evidence-pack.md（已查證的來源，可用、可另外補充）、inputs/experience.md（作者經驗；不存在時，選題建議只依證據與競爭缺口）。

產出：outputs/A.md
1. 名詞重點：Search Intent、Micro Search Intent、E-E-A-T、YMYL 各 3–5 點，附來源。
2. 微意圖表（至少 4 個）：意圖一句話、使用者處境與他下一步要做的決定、當下情緒、真實證據（來源連結或證據包代號＋短引）、目前搜尋結果怎麼回答與缺口、這篇文章的內容機會。
3. SEO 競爭邏輯：為什麼切入這些微意圖，而不是直接寫「娛樂城推薦」。
4. 選題建議：推薦 2 個意圖並說明理由，評估作者經驗最能支撐哪個意圖（具體指出 inputs/experience.md 哪幾句能用、還缺什麼）。

品質要求：
- 意圖必須有真實證據支持（真的有人這樣問、真的常發生），每條證據可以查證。新增來源只有實際開啟、核對過短引的才標「已開啟」，其餘標「搜尋摘要」。
- 4 個意圖的「下一步決定」彼此不同，不是同義改寫。
- 事實與推論分開寫；沒有搜尋量或排名資料就直接說未知，不要估計。搜尋工具回傳的順序不是 Google 排名。
- 業者與導購頁不列網址與品牌。
```

## 階段 B

### `prompts/B1.md`

```text
【B1｜作者經驗訪談】
目標：為選定意圖的文章取得「無法被 AI 偽造」的第一手細節。

輸入：outputs/A.md、outputs/decision-log.md（選定的意圖與理由）、inputs/experience.md（作者已回答的內容；可能不存在）

產出：outputs/B1-questions.md，讓作者一次回答。
- inputs/experience.md 不存在：約 10 題，先問作者和這個題目的關係（玩過什麼、多久、用什麼管道、在哪裡、有沒有利益關係），再問選定意圖需要的細節。
- inputs/experience.md 已存在：只補問選定意圖還缺的細節，6–8 題。
- 每題附一句「這題要補文章哪一段」。檔案開頭一句說明用途與作答方式：可以跳題、金額時間寫大概、不寫平台名稱。

品質要求：
- 先對照選定意圖，列出文章需要、但作者經驗還沒有的細節，再出題；已回答過的不重問。
- 問題具體，能問出畫面上的字、步驟順序、等待時間、金額大概範圍、自己當時怎麼算、最後怎麼決定、事後怎麼看。
- 第一人稱能不能寫，取決於作者在哪裡、用什麼管道參與（在台灣以網路賭博財物觸犯刑法第 266 條）。需要時用中性的方式問清楚，並說明只用來決定文章怎麼寫、不會寫出地點細節。
- 不誘導作者給出特定答案；沒經歷過的可以跳過。
- 不問會識別作者或平台的資訊（平台名稱、帳號、付款資訊、真實日期）。
```

### `prompts/B2.md`

```text
【B2｜玩家視角文章】
目標：寫一篇對搜尋選定意圖的人真正有幫助、讀起來像台灣資深玩家獨立心得的文章。一次寫到可以送審：內容、查證與口吻都要到位。

輸入：outputs/decision-log.md（選定意圖與給 B 段的範圍限制）、outputs/A.md（該意圖的證據與缺口）、inputs/experience.md（作者經驗與使用限制）、evidence-pack.md、style-guide.md

產出：
- outputs/B-draft.md，正文 3000 中文字以上，依 style-guide.md 的「一、共通」與「二、對外文章」寫作。
- 新開啟的來源：把文中用到的原文逐字摘錄附加到 outputs/sources-added.md（格式同 evidence-pack.md：標題、網址、取得日、以「>」開頭的原文），註明由 B2 新增。

品質要求：
- 有玩家試玩情境與客觀評論：評論說清楚用什麼標準評，優點都附條件或限制。感官細節（畫面上的字、數字、等待的感覺）只用作者經驗或來源裡有的；沒有素材就少寫，不補。
- 誠實：第一人稱經驗只用 inputs/experience.md 的作者原文，遵守使用限制，照原本的分量寫，不誇大、不補細節。超出作者經驗的情境寫成第三方案例或綜合重建（定義見 style-guide.md），情境裡的金額、天數、對話都要對得到來源。作者的個人看法寫成看法，標明適用範圍，並在客觀評論中用證據檢驗，證據不支持就照實寫。
- 揭露：開頭與結尾各一句，交代細節取材（作者本人經驗＋公開來源）、作者和題目的利益關係（依 inputs/experience.md）、文字由 AI 依作者訪談與公開資料整理、在台灣參與線上賭博（包含境外平台）有刑事責任；兩句都要包含「不推薦任何平台」這幾個字（機械檢查依此判定）。不寫出作者姓名、公司或可識別身分的資訊。
- 專業深度：用作者的專業觀點把條款與話術算清楚（例如期望值、為何「穩賺」在數學上不成立）；至少一處讀者可以自己重算的原創計算，寫明假設，引用的數字要可查證。
- 口吻：寫完以資深編輯的眼光重讀全文，把讀起來像 AI、像業配、太工整、像查核報告（正文交代查證過程、條文堆疊）或像小說（刻意鋪陳感官）的句子改成真實玩家會寫的樣子。
- 文末以「## 資料來源」為標題列出來源與取材說明（機械檢查以這個標題切分正文），依 style-guide.md 只寫讀者查證需要的內容；製作過程（證據包代號、核對經過、抓取方式）不寫進文章。
- 不推薦平台、不導流、不保證出金或獲利，也不教人規避銀行、KYC 或法律。業者與導購頁不列網址與品牌。
```

## 階段 C

### `prompts/C1-facts.md`

```text
【C1｜審核之一：正確性、YMYL 與權威性】
目標：以 Google E-E-A-T 與 YMYL 標準審核 outputs/B-draft.md 的事實、計算、法律與讀者安全，特別檢查 Authoritativeness（權威性）；並對照目前搜尋結果裡的競爭頁，找出這篇還缺什麼、贏在哪裡。你沒有參與寫作。作者經驗是否忠實、口吻像不像真人，由另外兩位審核者負責。

輸入：outputs/B-draft.md、evidence-pack.md、outputs/sources-added.md、outputs/A.md、outputs/decision-log.md、style-guide.md

產出：outputs/C-audit-facts.md
1. 問題表：編號（F1、F2……）、位置原句、問題、依據、嚴重度、修正建議。
   - 嚴重：可能讓讀者做出傷害金錢、法律或安全的決定，或構成事實錯誤。
   - 中：明顯降低可信度或權威性，但不會直接誤導讀者的決定。
   - 輕：措辭或呈現上的問題。
2. 事實與計算：
   - 每個數字是否有可信來源、計算是否正確（自己重算）；「」與英文引號內的引文是否逐字出自來源。
   - 術語的白話解釋（例如路單、流水、去水）是否對得到來源。
   - 第三方案例與綜合重建裡的具體細節（金額、天數、對話、畫面），逐項對到來源。
   - 推論是否寫成定論、轉述是否比來源說得更重。
3. 法律與讀者安全：法規、時限、金額以全國法規資料庫現行條文為準；是否把境外合規說成在台灣合法；是否在無意間鼓勵參與、導流、保證出金，或讓讀者延後求助（例如報案的順序）。
4. 缺漏：站在搜尋這個意圖的讀者處境，列出他做決定還需要、但文中沒有的資訊（例如下一步的官方管道、成本試算、成癮求助、法律風險），附依據與嚴重度。
5. 競爭情報：搜尋這個意圖目前的結果（可參考 outputs/A.md 的觀察），整理主要競爭頁怎麼回答；指出它們有、這篇沒有的有用資訊，以及它們誤導讀者、這篇該正面回應的說法。業者與導購頁不列網址與品牌。
6. 權威性評估：引用了哪些官方法規、公告或機構，來源能否查證，作者身分與利益關係是否交代清楚；和競爭頁相比權威性高在哪、低在哪。

為了核對而開啟的來源，把核對用的原文逐字摘錄附加到 outputs/sources-added.md（格式同 evidence-pack.md），註明由 C1 核對。

品質要求：每個問題都要有依據，不為了挑而挑；YMYL 風險（金錢、法律）優先。修正建議本身要符合 style-guide.md：揭露與免責只放開頭與結尾，查核日期與方法放文末資料來源，不建議在正文加免責句或查證說明。
```

### `prompts/C1-experience.md`

```text
【C1｜審核之二：作者經驗】
目標：確認 outputs/B-draft.md 裡每一句作者的第一人稱經驗與看法，都忠於作者本人說過的話。E-E-A-T 的 Experience 靠這些句子成立：說錯或說重一句，整篇的可信度就跟著倒。你沒有參與寫作。

輸入：outputs/B-draft.md、inputs/experience.md

產出：outputs/C-audit-experience.md
1. 對照表：逐條列出文中作者的第一人稱經驗、看法與背景陳述，包括開頭結尾的揭露與文末取材說明，每條對應 inputs/experience.md 標為「作者原文」各節的原句，判定為相符、說重、說輕、對不到或違反使用限制。作品摘要與使用限制是整理文字，用來判斷能寫的範圍，不當作原話。
2. 問題表：編號（E1、E2……）、位置原句、問題、對應的作者原文、嚴重度、修正方向。
   - 嚴重：對不到原文、說重、違反使用限制，或把作者的看法搬到他沒講過的情境（例如把他對某一類場所的看法，放進談詐騙平台的段落）。
   - 中：說輕到改變意思，或看法沒有標明適用範圍。
   - 輕：措辭貼近但不精確。
3. 需要作者確認的事：只有作者本人能回答的問題（某句是不是他的意思、某個看法能不能延伸到某個情境），每題附它影響的原句，以及作者不回答時的保守寫法。沒有就寫「無」。

品質要求：逐句對照，不抽查；不評文筆與事實正確性（另有審核者負責）。
```

### `prompts/C1-reader.md`

```text
【C1｜審核之三：讀者視角】
目標：以搜尋這個意圖的台灣讀者、也是資深論壇編輯的眼光讀 outputs/B-draft.md，找出讀起來不像真人玩家心得、讀者讀不下去，或讀完不知道該怎麼做的地方。你沒有參與寫作，也刻意不給你來源：你看到的就是讀者看到的。

輸入：outputs/B-draft.md、style-guide.md（「一、共通」與「二、對外文章」）、outputs/decision-log.md（只看選定的意圖與讀者處境）

產出：outputs/C-audit-reader.md
1. 讀後印象：三到五句，寫出讀完的感受：像誰寫的、哪裡想跳過、哪裡最有用、讀完會做什麼決定。
2. 問題表：編號（R1、R2……）、位置原句、問題（違反 style-guide.md 哪一條，或讀者會怎麼誤解）、嚴重度、修正方向。範圍：
   - 口吻：AI 腔、業配感、查核報告感（正文交代查證過程、條號與條文堆疊、統計推導）、小說或散文式的感官鋪陳、重複的免責與揭露。
   - 對讀者的態度：說教、貶低正在搜尋的讀者，或站在讀者的對立面。
   - 結構與密度：主線是否清楚、重點是否在前；讀者用不到的旁支；篇幅是否超出這個意圖需要的範圍。建議刪、縮、移到文末或拆成另一篇的內容，具體列出。
   - 易懂：沒解釋的術語、讀者看不懂的算式、無法照做的行動步驟。
   - 嚴重度：讀者會因此誤解或放棄閱讀為中，只是不夠自然為輕。
3. 讀得自然、該保留的段落：列出來，避免修正時被改掉。

品質要求：
- 每條附原句，修正方向具體到怎麼改。
- 你不核對事實，也不建議新增事實。涉及讀者安全的內容（法律後果、報案、求助管道、警語）可以建議改得更好讀或換位置，不能建議刪掉。
- 不為了挑而挑。
```

### `prompts/C2.md`

```text
【C2｜整合修正】
目標：依三份審核修正文章，讓事實正確、讀者安全、作者的話照原意，並在同一次修改中顧好口吻，讓全文讀起來仍是台灣資深玩家的論壇心得。三份審核的建議可能互相衝突（例如補法規與條號會讓文章像查核報告），由你判斷取捨。

輸入：outputs/B-draft.md（第一輪）或 outputs/C-revised.md（被 C3 退回或小修時）、outputs/C-audit-facts.md、outputs/C-audit-experience.md、outputs/C-audit-reader.md、outputs/C-recheck.md（被退回或小修時）、inputs/experience.md（含作者確認後的回答）、evidence-pack.md、outputs/sources-added.md、style-guide.md

產出：
- outputs/C-revised.md：修正後全文。
- outputs/C-changes.md：逐項對照（審核編號 → 原句 → 新句 → 理由）。審核建議彼此衝突、或和 style-guide.md 衝突時，寫明怎麼取捨。被退回或小修時在檔末追加一節，不覆蓋前一節。
- 新開啟的來源：把文中用到的原文逐字摘錄附加到 outputs/sources-added.md，註明由 C2 新增。

品質要求：
- 每個問題都有處理；不採用的寫明理由。需要作者本人才能補的照實註明，用審核者建議的保守寫法，不編造。
- 新增的權威來源必須實際開啟核對、附連結。法規、時限、金額以全國法規資料庫現行條文為準，宣導頁與新聞只當輔助。
- 改完依 style-guide.md 的「一、共通」與「二、對外文章」用絕對標準看全文口吻，不是和前一版比：
  - 正文只放讀者做決定需要的出處（誰說的、哪一條）；查核日期放文末「## 資料來源」；資料來源段只寫讀者查證需要的，製作過程（內部代號、核對經過、抓取方式、作者哪天確認）記在 C-changes.md。
  - 統計推導（信賴區間、常態近似）正文只留結論與白話，算式放文末「本文的計算與假設」。
  - 揭露與免責只在開頭與結尾各一句。
  - 法條與官方說法寫條號或機關名加白話；只有讀者需要逐字看的短句才保留引號。
  - 行動步驟每步開頭一句命令句，說明跟在後面；讀者用不到的旁支縮短。
- 不刪改事實：數字、算式結果、條號、機關、電話、讀者的行動與警語都保留，除非審核指出它是錯的；保留的「」引文逐字不改。作者第一人稱的內容不改意思。
- 不新增作者沒有的經驗；新增內容精簡，融入原本的口吻。
- 開頭與結尾的揭露句保留「不推薦任何平台」這幾個字；文末來源段標題維持「## 資料來源」。
- 小修時（C-recheck.md 的結論是「小修」）只改 C-recheck.md 列出的句子，其他一個字都不動。
```

### `prompts/C3.md`

```text
【C3｜全文獨立複審】
目標：像第一次讀到這篇文章的人一樣，從頭到尾審一遍修正後的全文，確認修正解決了問題、沒有引進新錯誤，判定能不能定稿，並清點自我修正的成果。修正最常在改動處和前後文之間出錯，所以要讀全文，不能只看修改處。你沒有參與寫作、審核或修正，只審不改。

輸入：outputs/C-revised.md（要審的稿）、outputs/B-draft.md（修正前）、outputs/C-audit-facts.md、outputs/C-audit-experience.md、outputs/C-audit-reader.md、outputs/C-changes.md、prompts/C1-facts.md、prompts/C1-experience.md、prompts/C1-reader.md（三份審核標準）、inputs/experience.md、evidence-pack.md、outputs/sources-added.md、style-guide.md

產出：outputs/C-recheck.md
- 每個原問題：已解決、未解決，或不採用是否合理，附理由。
- 全文重審，用三份審核的標準：
  - 事實與計算自己重算；C2 新增的來源與法規自己重新開啟核對。
  - 第一人稱逐句對 inputs/experience.md 的作者原文，包括使用限制。
  - 口吻依 style-guide.md 的「一、共通」與「二、對外文章」用絕對標準判斷，不只是和修正前比較。
  - 特別看修改處和前後文：說法有沒有前後矛盾，作者的話有沒有被搬到別的脈絡，修正有沒有只改了一半。

- 優化成果：B-draft.md 與 C-revised.md 的具體差異，數字從兩份檔案重新數，例如問題數與嚴重度、事實錯誤數、權威來源數、第一人稱陳述有無對應、揭露與風險說明、讀者行動管道、相對競爭頁補上的缺口。
- 結論，三選一：
  - 可以定稿：沒有未解決的嚴重或中級問題。
  - 小修：剩下的問題都能各改一兩句解決。逐條列出位置原句、問題與改法。
  - 退回 C2：有嚴重問題，或要改動整段以上。逐條列出位置原句與修正方向。
```
