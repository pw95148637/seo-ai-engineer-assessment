# 理論依據：用提示詞與系統設計確保 E-E-A-T

**E-E-A-T 不能靠 prompt 裡寫一句「請展現專業與可信」得到。** 模型被要求「像資深玩家」時，最自然的產出就是編造經歷：同一題只給題目的單一 prompt，寫出了「混了十五年」「朋友阿凱」「連續二十一個晚上抄了 412 注」，全部沒有出處。Google 把捏造作者身分與資歷視為欺騙（Creating helpful content），Trust 又是四項中最重要的（Search Quality Rater Guidelines §3.4）。所以這條鏈的原則是：每一項 E-E-A-T 都要有真實來源，並由不是寫作者的人或程式檢查。

| 要素 | AI 常見漏洞 | 怎麼確保 | 在系統哪裡 |
|---|---|---|---|
| Experience（經驗） | 虛構第一人稱經歷與感官細節 | 作者本人受訪；第一人稱只能出自訪談原文並遵守使用限制；別人的經驗寫成交代出處的第三方案例；審核者逐句對照原文，只有作者知道的事回頭問作者 | B1、B2、C1 作者經驗審核；`inputs/experience.md` |
| Expertise（專業） | 空泛建議、看似專業但算錯的數字 | 用作者真實的專業（自建預測模型的 970 場樣本外驗證）回答讀者的問題；至少一處讀者能自己重算的計算；主控與審核者各自重算 | B2；主控關卡；C1 正確性審核、C3 |
| Authoritativeness（權威） | 引二手轉述、過時規定、沒有來源 | 事先查證的來源清單與官方原文優先；法規以全國法規資料庫現行條文為準；對照目前搜尋結果的競爭頁，補上缺口、回應誤導 | `evidence-pack.md`；C1 正確性審核（含競爭情報）；C2 |
| Trust（可信） | 隱藏利益關係與 AI 使用、引文改字 | 開頭與結尾揭露取材、AI 整理、作者的產業身分與利益關係、不推薦平台；「」引文由程式比對來源原文 | B2；`tools/check_article.py --quotes` |
| YMYL 安全 | 推薦平台、淡化風險、讓讀者延後求助 | 不推薦、不導流、不教規避；站在讀者處境找缺漏（報案順序、帳戶限制、二次詐騙、成癮求助） | C1 正確性審核；C1 讀者視角審核；C3 |

**讓規則真的生效的四個設計**

1. **寫的人不審自己，而且依錯誤類型分頭審。** 三種錯誤需要的資料不同：正確性要來源，作者經驗要原話，讀者視角則刻意不給來源。拿著來源的審核者會用查核者的眼光讀，看不出文章已經像查核報告；上一版的口吻問題，全是盲評評審抓到的。
2. **最後一步一定是檢查。** 修正本身會引進錯誤：上一版修正時引進過 4 條錯誤，只驗修改處的精簡版本則漏掉一個修一半的句子。所以每次修改後，都有沒參與的人從頭讀全文（C3）或驗差異（C4）。
3. **重複的比對交給程式。** 字數、揭露位置、AI 腔字詞、引文是否逐字出自來源、修改後有沒有少掉數字，由腳本量；引文比對只認來源原文，不認文章自己的句子。
4. **同一把尺。** 寫作、審核、修正與盲評都依 `style-guide.md` 判斷「像不像真人」。

**實際效果（這次執行，修正前 → 定稿）**：三份審核共 53 條（嚴重 8），全部處理；作者第一人稱 50 句中 11 句對不到或說錯分量，定稿 42 句全部對得到作者原話；事實或轉述錯誤 6 → 0；官方、法規與監管機關來源 6 → 12；「已經出事怎麼辦」從正文 89% 處移到 34% 處。盲評時評審列出的缺陷平均 1.3 條，同資料單一 prompt 是 3.7 條。細節見 `C-result.md`。

**原題 C 段的「Hermes 自主 SEO 競爭情報 Agent」**：這句和第二題的標題相同。本鏈的對應是 C1 正確性審核，每次執行都搜尋目前的競爭頁，整理缺口與誤導說法交給修正；持續運作、會累積經驗的自主競爭情報 agent 在第二題實作。

**限制**：盲評評審和寫作者是同一個模型家族；評審沒能完全不載入專案說明；每組只有一篇；搜尋結果來自搜尋工具，不是 Google 台灣的實際排名；法律段沒有經過律師審閱。
