# 娛樂城提示詞鏈

把語意模糊的關鍵字「娛樂城」，轉成一篇有作者第一手經驗、經過 E-E-A-T／YMYL 自我審核的台灣玩家心得文。在 Claude Code 裡輸入 `/prompt-chain` 就會跑完整條鏈：每一步交給新的 subagent，主控依關卡檢查、退回修正，最後和單一 prompt 盲評比較。這是搜樂 AI 工程師測驗任務一的作答；完整報告與簡報的連結在 repo 首頁。

**成果在 `deliverable/`**：A、B、C 三階段結果、最終文章、prompt 全文、架構圖、理論依據與迭代紀錄。每次執行的完整過程（`outputs/` 是系統 v4，`outputs-<版本>/` 是舊版；各步產出、審核、盲評與當時的系統快照 `system/`）逐句引用作者訪談，不放在公開 repo，以 Drive 上的壓縮檔提供給公司（連結也在四題總覽）。

**主要發現：** 品質主要來自輸入（事先查證的來源與作者本人的經驗）和「沒參與的人把全文從頭讀一遍」，不是寫作步驟的多寡。現行 v4 只寫一次，三份審核依錯誤類型分頭進行。和上一版 9 步的完整鏈比，總分 22.3 對 22.7、真人感 3.7 對 2.7，成本約為一半（送評版相比）；v4 送評版被列的 3 條輕微缺陷都成立、盲評後已修正，上一版則吸收過四輪盲評回饋。給相同資料的單一 prompt 總分 19.0，缺陷 3.7 條。

## 怎麼跑

需要 Claude Code v2.1.271 以上（對照實驗用到 subagent 的 `omitClaudeMd` 設定）與 Python 3.8 以上。文件裡的指令都寫 `python`；系統上只有 `python3` 時照樣替換，並同步修改下面第 2 步的權限範本。

1. 在這個資料夾開 `claude`，接受資料夾信任提示。
2. 選用：把 `.claude/settings.example.json` 複製成 `.claude/settings.json`。它放行查網頁、`tools/` 的五支腳本，以及寫入 `outputs/`、`deliverable/`；不複製也能跑，只是 subagent 每次上網都會詢問。
3. 作者本人的經驗放在 `inputs/experience.md`。公開版不附本作答作者的訪談；沒有這個檔時，鏈在選題後會先出訪談題目，作者的回答存成這個檔。
4. 輸入 `/prompt-chain`，或說「跑提示詞鏈」。已有 `outputs/` 時，主控會先把它改名為 `outputs-<版本>/`。
5. 看過 `outputs/final.md` 與 `outputs/run-summary.md`、確認品質後，說「產出交付成品」，主控會產出 `deliverable/`。

作者在線時最多停兩次：選題後補問作者經驗，以及審核後確認只有作者能回答的事。某一步重試兩次仍不過關時，主控也會停下來問。完整跑一次約 2 小時，大部分時間花在 subagent 上網查證。

## 流程

```
A 微意圖建模 → 主控選題 →（作者經驗不足時）B1 補問作者 →【作者回答】→ B2 寫作
  → C1 三份審核同時進行（正確性與 YMYL｜作者經驗｜讀者視角）→【作者確認】
  → C2 整合修正 → C3 全文獨立複審 → 定稿／小修（C2 只改那幾句 → C4 驗差異）／退回 C2
對照實驗：同一題由單一 prompt 寫，連同上一版系統的定稿，三位評審盲評並列缺陷 → comparison.md → run-summary.md
```

| 步驟 | 執行者 | 產出 | 關卡（通過條件，摘要） |
|---|---|---|---|
| A 微意圖建模 | subagent | `A.md` | 至少 4 個意圖，各有可查證據，讀者讀完要做的決定各不相同；有競爭邏輯；不估計搜尋量；主控抽查 2 條新來源 |
| 選題 | 主控 | `decision-log.md` | 依證據強度、讀者決定是否明確、競爭缺口、作者經驗能撐多少，寫明選誰、放棄誰；YMYL 風險無法控制的直接排除 |
| B1 補問作者（作者經驗不足時） | subagent＋作者 | `B1-questions.md`、`inputs/experience.md` | 只問選定題目還缺的細節，不問可識別身分的資訊 |
| B2 寫作 | subagent | `B-draft.md` | 一次寫到可送審；機械檢查通過；第一人稱都對得到作者原文；計算由主控重算 |
| C1 三份審核 | 3 個 subagent（未參與寫作） | `C-audit-facts.md`、`C-audit-experience.md`、`C-audit-reader.md` | 每條有依據與原句；作者經驗逐句對照；讀者視角不拿來源、不建議刪讀者安全內容 |
| 作者確認 | 作者 | `inputs/experience.md` | 只問只有作者能回答的事；不回答時用保守寫法 |
| C2 整合修正 | subagent | `C-revised.md`、`C-changes.md` | 每條都處理或寫明不採用；衝突的取捨說得通；引文逐字、數字不少（程式比對）；口吻用準則的絕對標準 |
| C3 全文複審 | subagent（未參與寫作、審核與修正） | `C-recheck.md` | 只審不改；讀全文，特別看修改處和前後文；結論為定稿、小修或退回 |
| C4 小修驗證 | subagent（同上） | `C-verify.md` | 差異只含要修的句子；每處 PASS 才定稿 |
| 對照與盲評 | subagent | `baseline*.md`、`review-blind-1～3.md`、`comparison.md` | 同一題；評審各自隨機代號、列出缺陷；主控回到來源核對評審列的缺陷，成立的走小修 |

各步 prompt 在 `prompts/`，關卡與重試規則在 `.claude/skills/prompt-chain/SKILL.md`。

## 設計重點

- **經驗只來自真人。** 作者提供第一手經驗，AI 負責查證、組織、審核。第一人稱只能出自 `inputs/experience.md` 的作者原文；別人的經驗寫成第三方案例或綜合重建，細節都要對得到來源。
- **寫的人不審自己，而且依錯誤類型分頭審。** 正確性審核拿來源、可上網；作者經驗審核只拿作者原文；讀者視角審核刻意不給來源，因為拿著來源的人會用查核者的眼光讀，看不出文章像查核報告。
- **最後一步一定是檢查。** 修正本身會引進錯誤，所以每次修改後都有沒參與的人讀全文（C3）或驗差異（C4），不會以修改收尾。
- **重複的比對交給程式。** 字數、揭露位置、AI 腔字詞、引文是否逐字出自來源、修改後有沒有少掉數字、盲評代號洗牌與分數彙整、成本換算，都由 `tools/` 的腳本處理，主控只做判斷。
- **同一把尺。** 寫作、審核、修正與盲評都依 `style-guide.md` 判斷文體。
- **不預設鏈比較好。** 同一題另由單一 prompt 寫，連同上一版系統的定稿一起盲評，結果不利也照實寫。

## 目錄

| 路徑 | 內容 |
|---|---|
| `deliverable/` | 交付成品 |
| `prompts/` | 各步 prompt；`baseline*.md`、`review-blind.md` 是對照實驗用 |
| `.claude/skills/prompt-chain/SKILL.md` | 主控的流程、關卡、停點與重試規則 |
| `.claude/agents/isolated.md` | 不載入 CLAUDE.md 的 subagent，給對照組 1 與評審用 |
| `style-guide.md` | 寫作準則：文章、交付文件、系統文件 |
| `evidence-pack.md` | 事先查證的來源，逐字摘錄並標明查核程度 |
| `inputs/experience.md` | 作者經驗：作者原文、作品摘要、第一人稱的使用限制（公開版不收） |
| `tools/` | `check_article.py`（文章機械檢查）、`make_blind.py`（盲評副本）、`aggregate_reviews.py`（彙整評分）、`export_prompts.py`（匯出 prompt 全文）、`cost_report.py`（依牌價換算成本），都支援 `--help` |
| `outputs/`、`outputs-<版本>/` | 每次執行的各步產出、`run-log.md`、`run-summary.md`、`comparison.md`、`cost.md`，以及當時的系統快照 `system/`（公開版不收，以 Drive 上的壓縮檔提供給公司） |
| `SYSTEM_CHANGELOG.md` | 每項系統變更的原因與依據 |
| `第一題指引.md` | 題目原文、解讀與各項要求的對應（含題目原文，公開版不收） |

## 限制

- 盲評的評審和寫作者是同一個模型家族，可能偏好相近的文風；每組各一篇，分數差距小時要保守解讀。
- `isolated` agent 依官方文件設定，實際執行時沒能用上：主控的工作階段從另一個專案啟動，評審改用一般 subagent，以派工訊息限定可讀的檔案（見執行紀錄壓縮檔的 `outputs/comparison.md`「限制」）。
- 沒有搜尋量與 Google 台灣的實際排名資料，選題的競爭判斷依搜尋工具樣本與公開文件，上線後要用 Search Console 驗證。
- 文章的法律段落未經律師審閱。
